# Enterprise Deployment, Security & Operations

This document outlines the operational and security requirements necessary to graduate this prototype into a production-grade enterprise deployment within a government (FedRAMP) context.

## 1. Security & Threat Model

*   **Data at Rest Encryption:** All data stored in the PostgreSQL RDS instance and the S3 Object Storage must be encrypted using AWS KMS Customer Managed Keys (CMKs).
*   **Data in Transit Encryption:** All internal communication (ALB to ECS, ECS to RDS/Redis) must run over private subnets. External access via the API Gateway requires TLS 1.2+.
*   **Secrets Management:** The prototype currently uses environment variables. In production, sensitive API keys (e.g., OpenAI, AWS credentials) must be injected securely at runtime via **AWS Secrets Manager** or **HashiCorp Vault**.
*   **Network Boundaries:** To satisfy strict outbound traffic rules, the public OpenAI API must be replaced with an **Azure OpenAI** instance provisioned inside the agency's private VNet/VPC, ensuring no sensitive label data traverses the public internet.
*   **Data Retention & PII:** Compliance workflows dictate specific document retention policies. Object lifecycles in S3 must be configured to automatically purge or archive labels after a defined period (e.g., 90 days post-approval) to prevent unbounded data growth and minimize PII exposure.

## 2. Operations & CI/CD

*   **Continuous Integration / Deployment:** The current `deploy.zsh` script should be replaced by a formalized CI/CD pipeline (e.g., GitHub Actions, GitLab CI). The pipeline must enforce automated testing (`pytest`), linting, and container security scanning (e.g., Trivy, Snyk) before building and pushing Docker images to Amazon ECR.
*   **Database Migrations:** Changes to the PostgreSQL schema must be strictly version-controlled using **Alembic** (for SQLAlchemy), running automatically as part of the CD deployment phase.
*   **Logging & Monitoring:** Standard output from the ECS Fargate tasks should be aggregated into **AWS CloudWatch** or **Datadog**. Alerts must be configured for Celery task failures, high memory utilization, and API latency breaching the 5-second SLA.

## 3. COLA Integration API

To support the transition from manual uploads to automated, asynchronous ingestion directly from the COLA system, the FastAPI backend exposes formal endpoints. 

The integration team can interact with the system programmatically:
- `POST /jobs`: Submit a new label and application document payload. Returns a `job_id`.
- `GET /jobs/{job_id}`: Poll for completion status and retrieve the structured JSON compliance report.

The formal OpenAPI (Swagger) specification is automatically generated by FastAPI and is available at the `/docs` endpoint of the running backend.
